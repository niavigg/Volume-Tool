# VolumeTool v1.0

给**物理音量键坏了 / 不方便按**的设备准备的音量控制工具。

## 下载

`VolumeTool-v1.0.apk` —— 直接安装即可，覆盖旧版本无需卸载（同一签名）。

最低支持 Android 8.0（API 26），编译目标 API 34。

## 四种调音量的方式，全部实时同步

| 方式 | 说明 |
|---|---|
| 悬浮窗 | 任何界面都能调。平时是小圆显示当前音量，点一下展开成药丸（左 − 右 +），可拖动，闲置自动收起 |
| 常驻通知 | 四个按钮：音量+ / 音量− / 切换 / 静音（折叠态显示前三个） |
| 状态栏磁贴 | 音量+、音量−、媒体·铃声切换、悬浮窗开关，共四个 |
| 屏幕大按钮 | 点一下调一格，长按连续调节 |

**媒体 / 铃声全局切换**：在通知栏、状态栏、首页任意一处切换，其余地方立刻跟着变，不会出现"通知里是铃声、别处还在调媒体"的情况。

## 装好后要做两件事

1. 授权**悬浮窗权限**，授权后悬浮窗会自动出现（不用切回主界面开开关）
2. 状态栏磁贴需手动添加：下拉快捷设置 → 编辑 → 把四个磁贴拖进去

## 已知限制

- 部分 ROM（MIUI / ColorOS）还需要额外打开「后台弹出界面 / 后台显示悬浮窗」，这是系统限制，应用无法绕过
- 悬浮窗可能会压住主界面上的按钮，把它拖到别处即可

## 兼容性处理（给同类应用参考）

1. **部分机型（OPPO / 一加 ColorOS 实测）会静默吞掉 `setStreamVolume()` 的写入** —— 调用不报错、返回值正常，但音量纹丝不动。本项目改用「逐级降级 + 写后校验」：先 `setStreamVolume`，写完立刻读回来验证，没生效就退到 `adjustStreamVolume`，再不行带 `FLAG_SHOW_UI` 重试。
2. **悬浮窗存活检测不能用「定时轮询 + `isAttachedToWindow()`」** —— 退出宿主界面后该值会短暂为 false，导致窗口被反复拆除重建，触摸事件全部丢失（表现为"离开主界面就点不动"）。正确做法是 `ViewTreeObserver.OnWindowAttachListener`，只在真被摘掉时补回。

## 构建

零第三方依赖，不用 Gradle / androidx：

```bash
export ANDROID_SDK=/path/to/android-sdk   # 含 build-tools/34.0.0 与 platforms/android-34
export JAVA_HOME=/path/to/jdk
./build.sh
```

产物在 `dist/VolumeTool-v<version>.apk`。仓库内的 `dist/volume.keystore` **不入库**，请用你自己的密钥签名。
